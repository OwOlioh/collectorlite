逆向 B 站 WBI 签名：从抓包到复现

知乎 · 3.2 万赞

WBI 签名是 B 站在 2023 年推出来的一套接口鉴权方案，核心目的是把请求参数做一次混淆，让直接构造 URL 爬接口的成本变高。

一、混合密钥表是怎么来的

先请求 nav 接口，返回体里有 img_url 和 sub_url 两个字段。把这两个 URL 的最后一段文件名去掉扩展名，就得到了 img_key 和 sub_key。

然后把两个 key 拼起来，按一张固定的 64 位映射表重排，取前 32 位作为新的密钥。这张映射表是写死在客户端里的，全站通用。

二、签名参数的生成

拿到混合密钥之后，把所有请求参数按 key 字典序排序、拼成 query string，追加上当前时间戳 wts，最后对整串做一次 MD5。

这里有个坑：参数值里如果有中文或者特殊字符，必须先做一次 URL 编码再参与拼接，否则算出来的签名在服务端校验一定失败。很多人卡在这一步，以为是自己密钥算错了。

三、为什么它拦不住人

因为映射表是公开的、算法是纯客户端的，只要能跑 JS 就能复现。它提高的是批量爬取的工程成本，不是安全边界。

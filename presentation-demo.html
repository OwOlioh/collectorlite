01

项目定位

Local-First Collector

把散落在五个平台的收藏汇聚进一个本地库，提供跨源检索、标签整理与笔记联动。

TAURI 2 + SQLITE
02

为什么做

5 Platforms · 0 Entry

收藏散落、平台会失效、无法统一检索、误删即永久丢失——现有方案全都解决不了。

索引与入口，非离线归档
03

分层架构

React ↔ Rust ↔ SQLite

前端经约 60 个 IPC 命令调 Rust 后端；后端分命令层、适配器层、笔记与桥接层。

RUST 8.6K + TS 5.6K 行
04

多源导入

SourceAdapter × 5

B 站 / 知乎 / CSDN / GitHub / 浏览器书签统一走一套 trait，新平台只需实现三个方法。

预览白名单机制
05

统一收藏库

Search · Filter · Sort

网格与列表双视图、全字段检索、来源与标签组合筛选、多选批量操作、虚拟滚动。

FTS5 全文检索
06

标签体系

Category → Tag → Item

三层结构，命名空间隔离来源自动带入的标签，支持相似标签合并与拖拽归类。

127 标签 / 11 分类
07

Obsidian 联动

One-Way · Scoped Sync

批注生成 Markdown，仅覆盖 collector 托管区，你在 Obsidian 里写的内容永不被冲掉。

删除收藏不删笔记
08

回收站

Soft Delete + Retention

所有删除均为软删除，先进回收站；保留期可配置，启动时自动清理超期条目。

7 / 15 / 30 天可选
09

跨源去重

Composite Unique Key

BV 号、回答 ID、仓库全名互不相通，用 (source, external_id) 复合键天然隔离，写入走 upsert。

(source, external_id)
10

封面本地化

WebView ≠ Host Proxy

WebView 不继承宿主进程代理，直连 CDN 必失败；改由 Rust 侧下载到 covers/ 并本地加载。

cover_local_path
11

路径校验陷阱

canonicalize \\?\ Prefix

Windows 上 canonicalize 给已存在目录加 \\?\ 前缀，首次写入目标没有——前缀比较恒为假，导出全被误拒。

改为纯词法规范化
12

发布版闪退

LF → CRLF Checksum

CI 的 autocrlf 改了迁移文件行尾，与数据库记录的校验值不符，启动即 panic。

构建成功 ≠ 能运行
